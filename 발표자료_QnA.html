Unrailed! 모작 — Q&A 대비 자료

예상 질문 & 답변 정리 · 발표 시연 후 질의응답용 · 이현렬 · 허찬휘

구조 렌더링 맵·충돌 레일 기차 자원·승패 입력·사운드 전체화면 성능 트러블슈팅
🎤 발표 팁 — 역할상 이현렬은 레일·기차·폭탄·승패 질문, 허찬휘는 플레이어·맵·장애물·자원 질문을 맡으면 자연스럽습니다. ★ = 이현렬 담당 영역

1. 전체 구조 / 게임 루프

Win32 API + GDI+ · C++ · 단일 main.cpp (약 2,800줄)
게임 루프는 어떻게 돌아가나요?
WM_TIMER를 16ms 주기로 돌려 게임 상태(이동·기차·자원 등)를 갱신하고 InvalidateRect로 다시 그리기를 요청합니다. 실제 그리기는 WM_PAINT에서 합니다. 이동량은 deltaTime(이전 프레임과의 시간차)을 곱해, 프레임이 흔들려도 속도가 일정합니다.
화면 전환(시작화면, 일시정지 등)은 어떻게 관리하나요?
GameState 열거형으로 관리합니다. STATE_START · GAME_START · PLAYING · PAUSE_MENU · SETTINGS · CONTROLS 상태에 따라 업데이트/렌더링을 분기합니다. 예) 메뉴 상태에선 게임 갱신을 건너뜁니다.
왜 단일 파일로 작성했나요?
학습/제출용 규모라 한 파일에서 흐름을 빠르게 파악하기 위해서입니다. 함수 단위로 영역(맵·플레이어·레일·기차·UI)을 나눠 관리했고, 규모가 더 커지면 파일 분리도 고려할 수 있습니다.

2. 렌더링 (GDI+ · 분할화면)

더블 버퍼링 + 위/아래 분할 + 카메라
화면 깜빡임은 어떻게 막았나요? (더블 버퍼링)
메모리 DC(memDC)에 맵·레일·기차·UI를 모두 그린 뒤, 마지막에 한 번에 화면으로 복사(PresentBackBuffer)합니다. 화면에 직접 그리지 않아 깜빡임이 없습니다.
2인 분할화면은 어떻게 구현했나요?
같은 memDC에 Graphics 두 개(g1 위/P1, g2 아래/P2)를 만들어, 각각 클리핑 영역을 위/아래 절반으로 잡고 카메라 이동량만큼 좌표를 평행이동(TranslateTransform)해서 그립니다. 각 플레이어를 따라가는 카메라(cam1·cam2)가 따로 있습니다.

3. 맵 / 충돌

이미지 기반 지형 · 픽셀 단위 충돌
충돌 판정은 어떻게 하나요?
맵 이미지를 로드할 때 LockBits로 픽셀을 한 번 분석해 비트마스크로 캐싱합니다. 초록 픽셀 = 걷는 땅, 그 외 = 충돌, 파랑 = 물. 플레이어가 이동할 위치의 픽셀이 충돌이면 막습니다. 매 프레임 이미지를 다시 읽지 않아 빠릅니다.
맵 크기는 무엇으로 정해지나요?
MAP_WIDTH × MAP_HEIGHT(타일 격자, 현재 60×30)와 맵 이미지 크기(1920×960)를 함께 맞춥니다. 타일 32px 기준으로 두 값이 일치해야 카메라 범위와 배경이 어긋나지 않습니다.

4. 레일 시스템 ★

자동 방향 감지 · 소유자 분리 · 색 구분
레일이 자동으로 꺾이는(커브) 건 어떻게 했나요?
설치하는 순간 상하좌우 이웃 레일을 보고 직선/커브를 결정합니다(AutoDetectRailDir). 가로 한쪽 + 세로 한쪽이면 해당 방향의 커브(4종)를 선택하고, 설치 시 주변 레일도 다시 계산해 자연스럽게 이어집니다. 커브 이미지는 한 장을 90/180/270° 회전해 표현합니다.
이미 이어진 직선 위에 레일을 놓아도 안 깨지게 한 방법은?
좌우가 모두 연결된 관통 레일은 가로 직선으로 고정(위아래면 세로 고정)하는 규칙을 코너 판별보다 먼저 둤습니다. 그래서 직선 위/아래에 레일이 생겨도 선이 꺾여 망가지지 않습니다. 
if(left&&right) return HORIZONTAL;  // 관통 보호
if(up&&down)    return VERTICAL;
두 플레이어의 레일은 어떻게 구분하나요?
ownerGrid로 타일마다 소유자를 기록하고, 자동 연결·기차 주행 모두 같은 소유자 레일만 인식합니다(HasRailOwner). 그래서 P1·P2 선로가 붙어도 서로 이어지지 않습니다. 시각적으로는 P1 붉은빛 / P2 푸른빛으로 색을 입혔습니다.
레일 위치를 어떻게 빠르게 찾나요? (자료구조)
grid[높이][너비] 2D 배열에 방향을, ownerGrid에 소유자를 저장해 O(1)로 조회합니다. 처음엔 레일 벡터를 매번 선형 탐색(O(n))했는데, 그리드로 바꿔 성능을 크게 개선했습니다.

5. 기차 ★

주행 · 회전 · 과열 · 탈선 경고
기차가 레일을 따라가는 원리는?
기차가 올라선 타일의 레일 방향을 그리드에서 읽어(GetRailDir) 진행 방향을 정합니다. 커브 타일에선 방향을 90° 전환합니다. 자기 소유 레일이 없는 칸으로 가면 탈선(패배) 처리됩니다.
회전이 부드러운 이유는?
방향이 바뀔 때 즉시 90° 스냅하지 않고, 표시 각도(renderAngle)를 목표 각도로 매 프레임 조금씩 보간합니다. 회전 속도는 TRAIN_ROT_SPEED 상수로 조절합니다.
과열 시스템은 어떻게 동작하나요?
주행 중 열(heat)이 HEAT_RATE만큼 오르고, 물을 채운 양동이로 기차에 닿으면 열이 내려갑니다. 열이 최대치에 도달하면 기차가 멈추고(패배가 아님), 물로 식혀 열을 내리면 다시 움직입니다. (F3 무한 모드에선 과열이 비활성화됩니다.)
탈선 위기 경고는 어떻게 띄우나요?
기차 진행 방향으로 커브를 따라가며 남은 레일 수를 세고(CountRailsAhead), 1개 이하이면 기차 위에 경고 이미지를 0.3초 간격으로 깜빡입니다.

6. 자원·제작·설치 / 승패 ★

자원 채집과 제작은 어떻게 이어지나요?
플레이어가 자원 범위에 들어가면 진행도가 차오르며 자동 채집되고, 다 캐면 나무·돌이 인벤토리에 들어갑니다. 기지의 제작대에 닿은 채 일정 시간이 지나면 자원을 소모해 레일/장애물/폭탄을 제작합니다.
승리·패배는 정확히 어떻게 판정되나요?
기차가 상대 기지에 닿는 순간:
  • 폭탄 적재 상태 → 기지 폭파, 도착시킨 쪽 승리
  • 폭탄 없음 → 빈손 도착, 그 플레이어 패배
그 외 장애물 충돌·레일 끊김이면 해당 기차의 주인이 패배합니다. 두 기차가 동시에 끝나면 무승부입니다. (과열은 패배가 아니라 기차가 멈추는 페널티입니다.)
폭탄은 어떻게 기차에 싣나요?
폭탄을 기차가 있는 위치에 설치하면 그 기차에 적재됩니다(기차당 1개). 기차가 아닌 타일에 설치하면 타이머 후 폭발해 주변 장애물을 제거합니다.

7. 입력 처리 / 사운드

키 입력은 어떻게 받나요?
이동·설치 등 대부분은 GetAsyncKeyState로 매 프레임 폴링하고, "이전에 안 눌림 → 지금 눌림"의 엣지를 감지해 한 번만 반응시킵니다. 토글 기능(F3 무한모드·F11 전체화면)은 더 확실하게 WM_KEYDOWN 이벤트로 처리하고 키 반복은 무시합니다.
소리는 어떻게 재생하나요? 볼륨 조절은?
PlaySound + WAV로 BGM·효과음을 재생합니다. 볼륨은 waveOutSetVolume으로 0~100을 적용하며 슬라이더와 연동됩니다. PlaySound는 한 번에 한 소리만 나서, 시작음→클릭음→기차음→플레이 BGM을 순차로 틀었습니다.

8. 전체화면 (F11)

전체화면은 어떻게 구현했나요?
내부 해상도는 1280×720 그대로 두고, 창을 WS_POPUP으로 바꿔 모니터 전체를 덮은 뒤, 백버퍼를 화면 크기에 맞춰 StretchBlt로 확대합니다. 16:9 비율을 유지(레터박스)하고, 늘어난 화면에서도 버튼이 맞도록 마우스 좌표를 다시 1280×720 기준으로 역변환합니다. 덕분에 버튼 좌표를 하나도 안 고쳤습니다.

9. 성능 최적화 (렉 해결)

"레일 많이 깔면 렉" → 원인별 해결
레일이 많아지면 렉이 걸렸는데 어떻게 잡았나요?
원인이 여러 개라 하나씩 잡았습니다:
  • 레일마다 매 프레임 GDI+ Save/Rotate/Restore(고비용) → 회전·색까지 미리 구운 이미지로 만들어 단순 1장 그리기로 변경 (호출 5단계 → 1단계)
  • 이웃 갱신이 전체 레일 O(n) 스캔 → 그리드 O(1) 조회로 변경
  • 렌더링이 느린 기본 보간 → NearestNeighbor 등 빠른 모드
  • Debug 빌드의 vector 검사 오버헤드 → Release 빌드
Debug와 Release 차이가 그렇게 큰가요?
네. Debug는 vector 접근마다 범위 검사가 붙고 컴파일러 최적화가 꺼져 있어, 매 프레임 수백 개를 도는 루프에서 몇 배 느립니다. Release로 바꾸는 것만으로도 체감이 크게 좋아졌습니다.
메모리는 많이 쓰나요?
아니요. 맵 이미지(~7MB)·백버퍼(~3.7MB)·충돌 비트(~0.4MB) 등 합쳐 ~12MB 수준이라, 렉의 원인은 메모리가 아니라 매 프레임 렌더링 비용이었습니다.

10. 트러블슈팅 사례

개발 중 겪은 버그와 해결 — 발표에서 좋은 이야깃거리
기억에 남는 버그가 있나요?
  • 커브가 반대로 그려짐 — 세로 레일이 위로 꺾일 때도 아래쪽 커브로 그리던 로직 오류를, 이웃 배치로 4방향을 정확히 판별하게 수정.
  • 직선 위 레일 놓으면 깨짐 — 관통 레일을 직선으로 고정해 해결.
  • P2 레일이 안 보임(무한모드) — 설치물 종류 순환 로직의 예외 처리 버그 수정.
  • 맵 크기 변경이 반영 안 됨 — 코드는 맞았고 Debug 빌드가 오래된 게 원인. 다시 빌드해 해결.
MP3 배경음이 안 됐다는데?
처음엔 MCI로 MP3를 재생하려 했으나 경로의 한글 문자 때문에 초기화가 실패했습니다. 그래서 음원을 WAV로 변환하고 한글 경로를 잘 처리하는 PlaySound로 바꿔 해결했습니다.
